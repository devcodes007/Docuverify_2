How it works

Four decisions, not one blind pipeline. Retrieval strategy, evidence sufficiency, and answer groundedness are each evaluated explicitly instead of assumed.

01 · Classify

Route the query

Simple lookups, concept comparisons, and multi-hop questions get different retrieval strategies — comparisons retrieve each concept separately; multi-hop questions are decomposed into sub-questions first.

02 · Retrieve

BM25 + Dense + Hybrid

Exact identifiers (HTTPException, Depends) match on lexical search; paraphrased questions match on semantic embeddings. Hybrid scoring combines both, normalized to a common scale.

03 · Evaluate & retry

Is that actually enough?

Top-k retrieval isn't assumed sufficient. An evidence evaluator scores coverage and confidence; if it's not enough, the query is reformulated using the specific gap and retried — up to three attempts.

04 · Verify

Fine-tuned groundedness classifier

A trained transformer — not another LLM prompt — checks the generated answer against the retrieved evidence: SUPPORTED, CONTRADICTED, or UNSUPPORTED. Failures trigger a retry, then an honest refusal.

Evaluation

Retrieval quality is measured, not assumed — Recall@k, Precision@k, and MRR are computed for each retrieval strategy separately and compared, alongside a baseline (single-shot dense RAG) vs. the full agentic pipeline.

About

DocuVerify v2 is an agentic RAG reference implementation: structure-aware ingestion, BM25/dense/hybrid retrieval, query classification with per-strategy retrieval plans, a bounded evidence-driven retry loop, and a fine-tuned transformer groundedness classifier that independently verifies generated answers before they're returned. Source, tests, the training pipeline, and the evaluation framework are in the repository.
